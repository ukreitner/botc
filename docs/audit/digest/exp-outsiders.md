## Group notes

1. **Effective-ability indirection is the single highest-leverage change in this group.** Six of eleven need it: the Hermit *is* every Outsider on the script; the Cannibal can hold the Zealot ability; the Storyteller holds a Minion ability via the Plague Doctor; the Boffin can give the Demon the Heretic/Ogre/Politician ability. Every `characterId == "<id>"` test in the engine (`StatusEffects.kt:37,94-103,148`, `InfoCalc.kt:126-127`, `WinCheck.kt:54`, `GameActions.validateSetupState`) is wrong for these. **Resolved by `mechanics/setup-and-identity.md` §B** (which landed after these character audits): use `Identity.actingRoles(state, lookup, player): List<ActingRole>` + `Player.grants: List<AbilityGrant>` + `GameState.floatingGrants`. The three cards' ad-hoc names translate as: Hermit's `effectiveCharacterIds` → `Identity.derivedGrants` already emits `ADD(every Outsider on the script, "hermit")`; the Plague Doctor's `StorytellerAbility` → `FloatingGrant(abilityId, sourceId="plaguedoctor", holder = GrantHolder.STORYTELLER)`; the Zealot's `GainedAbility` → `AbilityGrant(abilityId="zealot", sourceId="cannibal", mode = REPLACE)`, derived from the `Lunch` token by `Identity.reconcile`. `GameState.effectiveInPlayIds` (membership tests, `WinCheck.kt:24,75-77`, jinx lookup) is still needed on top — but **not** for `validateBag`, which stays seat-only.
2. **Five of eleven never wake** (golem, heretic, politician, puzzlemaster, zealot) and act at nomination / execution / any-time / game-end. `night_guide.json` is night-keyed and is the app's only prose surface, so `NightGuideEntry` needs `setup` / `day` / `end` channels. This affects far more than this group.
3. **`WinCheck` is the shared bottleneck.** Heretic wraps *every* advisory (final `map`, after saint / demons-dead / ≤2-alive / mastermind / vortox-dusk / mayor-dusk / leviathan); Politician needs a blocking `EndGameQuestion` the ST must answer before the result is final; Damsel needs a `damsel-guessed` advisory; Hermit inherits saint + heretic + klutz + politician + damsel. Day-engine §G already names the Heretic wrap — this group supplies the rest.
4. **Conditional-death night steps.** `hatter` and `plaguedoctor` fire *because* the holder died, and `NightScreen.kt:702,751-757` prints red "All holders are dead — usually skip" on exactly those rows. Night-engine §2's `actsWhileDead` set + positive badge fixes both (and barber/sweetheart/moonchild/poppygrower outside this group).
5. **Jinx data is the worst data problem here**: 4 missing (hatter), 4 missing (ogre), 7 missing + 2 wrong-worded (plaguedoctor), 3 stale texts (heretic), 1 missing (politician), 2 low-confidence (zealot). Two structural fixes are needed beyond the text: `GameData.activeJinxes` (`GameData.kt:23-26`) requires **both** ids in play, which makes every Plague Doctor jinx unreachable by construction — it needs `potentialJinxes(inPlayIds, scriptIds)`; and jinxes need a machine-readable `kind` (`"exclusive"`, `"poison"`, `"redirect"`) so `validateBag` and setup can *act* rather than display text.
6. **Setup requirements the app does not have**: puzzlemaster (exactly one `Drunk` token), snitch (a 3-set per Minion), hermit (`-0/-1` choice + Drunk shown identity + Ogre friend), damsel (Spy/Widow standing poison), heretic (exclusive-jinx validation). `validateSetupState` (`GameActions.kt:503-561`) covers only drunk/lunatic/marionette/fortuneteller. Make it a table-driven `SETUP_TOKEN_REQUIREMENTS`.
7. **Two silent wrong-info P0s that corrupt every downstream number**: the Ogre's alignment is never flipped (every Empath/Chef/Fortune Teller/Investigator/Undertaker calculation is wrong for the rest of the game), and the Puzzlemaster's setup `Drunk` token is never demanded (a whole game of Townsfolk info is true when one player's should be false). Both are cheap.
8. **New state shapes this group forces**: per-recipient bluffs (snitch — today's single `demonBluffIds` truncated at 3 makes per-Minion bluffs *unrepresentable*), reconciled by `setup-and-identity.md` §A into `BluffRequirement(recipient, size, stepId, allowInPlay, required)` + `Bluffs.requirements(state, lookup)`, which is richer than snitch.md's raw `bluffSets: Map<Long, List<String>>` — **use the requirement model**; `FloatingGrant`/`storytellerReminders` (plaguedoctor — records-and-memory §C already adds the latter); `hermitTokenMeaning` folded into the new `PlacedReminder.note`.
9. **Conflicts with the mechanics specs**, needing a lead decision: (a) `LedgerEntry`/`LedgerKind` (records-and-memory) vs `DayEntry`/`DayEntryKind` (day-engine) — two competing day-record types; these cards use `LedgerEntry` per the digest brief. (b) `ImpairmentSpan` (politician.md) has **no home** in the unified model — `Effect` has `createdCycle`/`until` but no closed-interval history, and `MalfunctionEvent` is per-night, not per-span; the Politician question, the Mathematician and the Plague Doctor death check all want it. (c) golem.md's `DeathCause.ABILITY_DAY` vs status-model's `KillCause(GOOD_ABILITY, "golem")` vs day-engine's `DeathCause.NOMINATION`. *(Resolved since: night-engine's `StepKey.variant` could not express "Hermit as Butler" — setup-identity's `ActingRole(abilityId, slotId)` + `NightStep.abilityId` supersedes it and deletes `nightRoleId`.)*
10b. **Late corrections from `mechanics/setup-and-identity.md`, applied to these cards** — flagged inline as `correction:`. The big one: **the Snitch × Marionette "Demon learns an extra 3" jinx is retired.** A raw-wikitext sweep found no Snitch jinx section, no Snitch entry among the Marionette page's 9 jinxes, and no `snitch` key in the official `jinxes.json`; `night_and_jinxes.json:98-102` is **stale repo data** (a data-accuracy item). The Marionette simply is not woken. The genuine six-bluff case is **Legion + Snitch** — a Legion seat registers as a Minion *and* as the Demon, so it receives **two separate 3-sets**, not one enlarged one. Also confirmed there: the Ogre is one of exactly three abilities flagged `worksWhileImpaired = true` (with Boffin and Bone Collector), and a Hermit removed from play at setup "may still be a bluff given to the Demon".
10. **`GameActions.assignCharacter` (`:46-53`) is unsafe and three cards depend on fixing it.** It leaves stale tokens on the changed seat *and* tokens elsewhere sourced from the abandoned character, contradicting "their previous character ability has no further effect on the game". Hatter, Damsel-via-Huntsman and Puzzlemaster all need `BecomeCharacter(clearOldTokens = true)` to sweep both directions and to drop `<old>:No ability` spent marks.
